# Yelp Autoresponder

Автоответчик для входящих сообщений **Yelp for Business** (biz.yelp.com). Официальный API сообщений Yelp закрыт, поэтому платформа работает через интерфейс браузера, как человек:

- **Playwright** (постоянный профиль Chromium) держит вашу залогиненную сессию Yelp и проверяет входящие;
- **LLM-«мозг»** (Claude API или любой OpenAI-совместимый сервер) пишет ответы от лица владельца бизнеса — по профилю, фактам и правилам из вашего конфига;
- **[UI-TARS](https://github.com/bytedance/ui-tars-desktop)** — визуальный GUI-агент как fallback: если Yelp поменял верстку и селекторы сломались, агент «смотрит» на скриншоты и кликает/печатает как человек;
- **Дашборд** (`http://localhost:8377`) — живая лента событий, кнопка паузы, список диалогов, переданных человеку.

## Как это работает

```
 ┌────────────┐   poll    ┌──────────────┐  история   ┌───────────┐
 │ biz.yelp.  │ ────────► │  Runner      │ ─────────► │ LLM-мозг  │
 │ com/inbox  │           │  (Playwright)│ ◄───────── │ (persona) │
 └────────────┘           └──────┬───────┘   ответ    └───────────┘
        ▲                        │
        │   1) DOM-режим: селекторы + человеческий набор текста
        │   2) fallback: UI-TARS GUI-агент (скриншоты → клики)
        └────────────────────────┘
```

Человекоподобность: случайная задержка «прочитал-подумал» перед ответом (45–240 сек), посимвольная печать с джиттером и паузами на пунктуации, рабочие часы, дневной лимит ответов, cooldown на диалог, джиттер интервала поллинга.

Безопасность: LLM обязан вернуть строгий JSON `{handoff, reason, reply}`. Спорные ситуации (злой клиент, претензии, возвраты, нестандартные запросы — настраивается) **не** отвечаются автоматически, а помечаются «нужен человек» и видны на дашборде.

## Установка

```bash
npm install
npx playwright install chromium   # если Chromium еще не установлен

cp .env.example .env                                  # ключи API
cp config/business.example.yaml config/business.yaml  # профиль бизнеса
```

Заполните:

- **`.env`** — провайдер LLM (`anthropic` / `openai-compatible` / `mock`) и ключи. Для UI-TARS fallback нужен развернутый эндпоинт модели UI-TARS (`UITARS_BASE_URL`, `UITARS_MODEL`) — например, [деплой на Hugging Face / vLLM](https://github.com/bytedance/UI-TARS-desktop/blob/main/docs/deployment.md). Без него платформа работает только в DOM-режиме (обычно этого достаточно).
- **`config/business.yaml`** — название бизнеса, персона, факты (цены, часы, услуги), правила, триггеры передачи человеку, рабочие часы и лимиты.

## Запуск

```bash
# 1. Один раз: войти в Yelp вручную (сессия сохранится в data/browser-profile)
npm run login

# 2. Прогон без отправки — посмотреть, ЧТО бот ответил бы (лог + дашборд)
npm run dry-run

# 3. Боевой запуск
npm start
```

Другие команды:

```bash
npm run once     # один проход по входящим и выход
npm run status   # счетчики, handoff-диалоги, последние события
```

Дашборд: **http://localhost:8377** — пауза/возобновление, лента событий, диалоги для человека.

## Структура

```
src/
  index.ts                 CLI (login / run / status)
  runner.ts                главный цикл: poll → read → LLM → send
  config.ts                .env + config/business.yaml (zod-валидация)
  humanize.ts              задержки, рабочие часы, «человеческая» печать
  store.ts                 состояние: на что ответили, лимиты, лента событий
  browser/session.ts       постоянный профиль Chromium, проверка логина
  yelp/selectors.ts        все селекторы biz.yelp.com в одном месте
  yelp/inbox.ts            список диалогов, чтение переписки
  yelp/composer.ts         отправка ответа через DOM (быстрый путь)
  agent/playwrightOperator.ts  UI-TARS Operator поверх страницы Playwright
  agent/guiAgent.ts        GUIAgent-обертка (визуальный fallback)
  brain/prompt.ts          системный промпт из business.yaml
  brain/responder.ts       Claude API / OpenAI-совместимый / mock
  dashboard/server.ts      мини-дашборд со статусом и паузой
```

## Настройка под себя

Все поведение — в `config/business.yaml`:

| Секция | Что задает |
|---|---|
| `business`, `persona` | от чьего лица и каким тоном писать |
| `facts` | цены, услуги, часы — то, чем модель может оперировать |
| `rules` | жесткие запреты (не обещать точную цену и т.п.) |
| `handoff_triggers` | когда молча передать диалог человеку |
| `behavior` | рабочие часы, задержки, лимиты, интервал поллинга |

## Важные оговорки

- **ToS Yelp**: автоматизация интерфейса Yelp нарушает их условия использования. Используйте на свой риск, на своем аккаунте. Встроенные лимиты и человекоподобные задержки снижают, но не исключают риск блокировки.
- Yelp периодически меняет верстку. Селекторы собраны в `src/yelp/selectors.ts` (несколько кандидатов на каждую точку); при полной поломке DOM-режима включается UI-TARS fallback, если он настроен.
- Первый запуск делайте через `npm run dry-run` и читайте, что бот собирается отвечать, прежде чем включать боевой режим.
